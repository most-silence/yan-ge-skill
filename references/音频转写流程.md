# 音频素材转写流程（小宇宙 / 抖音）

> 眼哥的主力素材是**小宇宙播客（近一年）** + **少量抖音视频**，都是音频，必须先转成文字才能蒸馏。
> 本文件定义：转写路线、落盘规范、清洗红线、分批策略。

---

## 1. 铁律：转写稿不润色

表达 DNA 藏在口语里：

> 原话：「这个票，怎么说呢，它就是——不是不好，是太贵了。」
> 被润色后：「该股估值偏高。」

前者能提取**风格**（犹豫、自我修正、用「贵」不用「估值」），后者只剩一个结论。

**禁止**：AI 总结、AI 改写、删口语、合并重复、补标点补成书面语。
**只允许**：去掉纯噪音（背景音乐段落、广告口播可标注后保留原文）。

---

## 2. 三条转写路线

| 路线 | 工具 | 中文质量 | 速度 | 成本 | 适合 |
|---|---|---|---|---|---|
| **A 现成工具**（推荐起步） | 剪映专业版「智能字幕」/ 通义听悟 / 飞书妙记 | 高 | 快（1 小时音频约 10–20 分钟） | 有免费额度 | 先跑 5–10 期验证流程 |
| **B 本地批量** | faster-whisper + ffmpeg | 中高（`small` / `medium`） | CPU 约 2–4× 实时 | 免费 | 一年全量、长期使用 |
| **C 云端 API** | 各家 ASR | 高 | 快 | 按量付费 | 量大且要快 |

### 本机现状（2026-10-21 实测）

| 项 | 状态 |
|---|---|
| Python | ✅ 3.11（Anaconda） |
| pip | ✅ 23.3.1 |
| git | ✅ |
| ffmpeg | ❌ 未安装 |
| yt-dlp | ❌ 未安装 |
| whisper / faster-whisper | ❌ 未安装 |
| NVIDIA GPU | ❌ 无 |
| E: 可用空间 | 209.9 GB |

**结论**：先用 **路线 A** 把手上的几期跑通，验证蒸馏流程；等要处理一年全量时再上 **路线 B**（无 GPU 时用 `small` 模型 + int8，夜间跑）。

### 路线 B 一次性准备（要做时再执行）

```powershell
python -m pip install -U faster-whisper
# ffmpeg 需单独装（winget install Gyan.FFmpeg 或 conda install -c conda-forge ffmpeg）
```

> 转写时长预估：无 GPU 的 `small` 模型约 2–4× 实时。50 小时音频 ≈ 13–25 小时机时，建议夜间分批跑。

## 3. 落盘规范

### 命名

```
YYYY-MM-DD_平台_标题关键词.txt
例：2025-03-14_小宇宙_为什么我不碰新能源.txt
例：2025-06-02_抖音_三个信号.txt
```

没日期就写 `0000-00-00_平台_标题.txt`，后补。

### 文件格式（必须带时间戳）

```markdown
# 元信息
平台：小宇宙
节目：XXXX
期数：第 12 期
日期：2025-03-14
时长：58:32
说话人：眼哥（单人）/ 眼哥 + 主持人
原始链接：<URL>
转写工具：通义听悟（或 faster-whisper small）

---

[00:00:12] 眼哥：……
[00:00:48] 眼哥：……
[00:02:31] 主持人：……
```

**时间戳是刚需**：Q1 原文溯源要靠它定位到「第几期第几分钟」，没有时间戳就没法回溯。

### 多说话人

访谈/连麦要标说话人。分不清时标 `[?]`，不要瞎猜。

## 4. 分批策略（滚动增量）

不要等一年素材全转完再开始——那会拖半年。按批推进：

| 批次 | 素材量 | 产出 | 档位 |
|---|---|---|---|
| **第 0 批** | 抖音现有几个视频 + 播客任选 3 期 | `SKILL.md` v0.1 骨架（能跑，覆盖 3 维） | 快速 |
| **第 1 批** | 再补 10 期（覆盖不同月份） | v0.2，补齐 01/02/03 维 | 增量 |
| **第 2 批** | 再补 20 期 | v0.3，补齐 04/05/06/07 维 | 增量 |
| **第 N 批** | 剩余全部 | v1.0，12 维达标 | 增量 |

**每批都走 [`增量协议`](../references/增量协议.md) 的 9 步**，盲评通过才升版本。

> 好处：早期就能用；每批都有对照基线（paired 三向）；不会因为素材没到齐而卡住。

## 5. 转写质检清单

每份转写稿入库前过一遍：

- [ ] 有时间戳（间隔 ≤60 秒）
- [ ] 有元信息头（平台/期数/日期/时长/链接）
- [ ] 说话人能区分（单人节目标「眼哥」）
- [ ] 无大段缺失（对比音频时长，文字量明显偏少要复查）
- [ ] 专有名词没被识别错（股票名、公司名、指标名——错一个可能毁一个维度）
- [ ] **没有被润色过**（出现「综上所述」「值得注意的是」这类书面语 → 疑似被 AI 改写过，退回）
- [ ] UTF-8 编码、无乱码（`�` 字符数 = 0）

> 专有名词错误是最高频的坑：ASR 常把「宁德时代」听成「宁德时代」还好，但「隆基绿能」「中际旭创」这类容易错。建议每份稿子跑一次关键词检查。

## 6. 从转写稿到 research 的映射

一份转写稿通常横跨多个维度，**不要按集切片，要按维度切片**：

```
sources/01-小宇宙转写/2025-03-14_xxx.txt
        ↓ 人工/Agent 摘录
research/01-投资哲学.md   ← 第 12 期 03:20 那段讲「赚谁的钱」
research/02-选股框架.md   ← 同一期 18:45 讲筛选标准
research/08-表达DNA.md    ← 全期口头禅
```

每条摘录在 `research/` 里必须带「期数 + 时间戳」，例如：

```markdown
- **来源**：第 12 期 `2025-03-14_为什么我不碰新能源` @ 18:45（一手）
```
