# 增量修改协议 · Pipeline B

> 已有 `SKILL.md` 之后，每次更新都走这 9 步。**不许裸改。**
> 核心原则：增量是「带纠错层的合并」，不是重写。

---

## 九步流程

### 1. 入口确认

- [ ] 确认这是「更新」而不是「新建」
- [ ] 读取现有 `SKILL.md` 的版本号与「调研截止」时间
- [ ] 判断新材料属于哪些维度（01–12）

### 2. diff

| 清单 | 内容 |
|---|---|
| 新增 | 新材料带来的全新信息 |
| 修改 | 与现有内容冲突、需要更正的 |
| 删除 | 已过时、被本人推翻的 |

### 3. 影响分析

列出依赖该内容的：
- 哪个心智模型 / 决策启发式
- 哪个章节
- 哪条索引引用（Q7 会查）

### 4. 快照

```
snapshots/YYYY-MM-DD-HHMM/
├── SKILL.md
├── PIPELINE_STATE.md
└── CHANGELOG.md
```

改前必须留。**没有快照不许动手。**

### 5. 合并

- 新材料归入对应段落
- 旧结论**保留**，标注「原结论 + 新证据（日期）」
- 仅在**明确矛盾**时修改，并写清「为什么改」
- 禁止整段重写覆盖

### 6. 纠错层

用户说「他不会这样，他会 xxx」时：

1. 写入 `SKILL.md` 的 `## 纠错记录` 段
2. 格式：`YYYY-MM-DD｜错误表现｜正确表现｜依据`
3. **立即生效**，不等下一轮

### 7. 盲评（棘轮判定）

- paired 三向：旧版 / 上次新版 / 本次新版
- N = 3 独立 judge，奇数多数决
- 本次 ≥ 上次 → **keep**
- 本次 < 上次 → 返工；连续两轮不达标 → **revert 到快照**

```bash
# 回滚用 revert，不用 reset --hard
git revert <commit>
```

### 8. 版本

- [ ] `SKILL.md` frontmatter / 正文
- [ ] `README.md`
- [ ] `CHANGELOG.md`

**三处必须同版本号。只写一处 = 没写。**
当日多次改动，当日必须补记（真实事故：只记了早上，下午全漏）。

### 9. 登记

- [ ] 更新 `PIPELINE_STATE.md` 的「最近更新」
- [ ] 更新 `SKILL.md` 的「调研截止」
- [ ] 跑 Q7 索引健康：引用路径失效 = 0、关键词失效 = 0
- [ ] 跑 Q9 合规检查：无买卖指令、无收益承诺、免责在位

---

## 四条禁止

| 禁止 | 原因 |
|---|---|
| 直接覆盖写 | 丢失旧结论与演进痕迹 |
| 跳过快照 | 出问题无法回滚 |
| 自己改自己评 | LLM 自评准确率仅 46.4% |
| 为凑分堆冗余 | 单轮涨幅 <1 分就该停手 |

---

## 触发增量的常见场景

| 场景 | 走哪几步 |
|---|---|
| 他发了新观点 | 1→2→3→4→5→7→8→9 |
| 用户纠正「他不会这样」 | 6→8（轻量，不必全流程） |
| 他翻车 / 公开认错 | 1→2→3→4→5（重点改维度 09/10）→7 |
| 新增一整批素材（如新书/新课） | 全流程，先做覆盖检查防重复蒸馏 |
| 只改错别字/格式 | 4→8→9 |
