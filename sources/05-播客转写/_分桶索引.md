## 为什么先分桶

规则名是批读员每批各自起的，同一条规则在 95 批里有 95 种说法：

```
120 分钟 120-25 跌破，那个位置就不是博弈多头点，该止损就止损
120 分钟破位 + 被套 + 弱势板块 → 该走就走
```

字面匹配抓不到。直接让 LLM 归并 2,612 条也不现实——上下文放不下，且无法逐条复核。
分桶把问题拆小：每桶几十到几百条，一个 subagent 能读完，产物可逐桶复核。

> **一条候选可以同时落进多个桶**（「120 分钟跌破就止损」既是均线也是止损）。
> 这是故意的——宁可重复，不可漏掉。归并阶段再去重。

## 下一步

每个桶交给一个独立 subagent 做**桶内语义归并**，产出：

1. 这个主题下他到底有哪几条规则（把 N 种说法收成 M 条）
2. 每条规则挂上所有支持它的期次 + 跨阶段次数
3. 冲突保留（同一主题下的相反说法，两条都在）

> 归并产物是「零件」，之后再把零件组装成「心智模型」——
> 顺序不能反。心智模型是归并的产出，不能当输入。
