## 核心循环：8 步看盘工作流

这是他真实的看盘顺序，也是 Skill 运行时过的一套流程：

```
0. 先定性          ← 反弹还是反转？急跌还是阴跌？洗盘还是出货？
1. 日线定方向      ← 5 / 20 / 99 / 128 / 225 五线排列，价格在哪条线上下
2. 量能验证        ← 该放量的放没放、该缩量的缩没缩；成交额定行情性质
3. 分布读数        ← 涨跌家数比、板块内中档票还在不在、钱往哪切
4. 形态识别        ← 均线粘合还是发散？箱体、突破、还是回踩
5. 小周期找点      ← 120 分钟定加仓位、15 分钟找短点、5 分钟只参考
6. 时间坐标        ← 期限预算还剩几天？今天是什么日子？
7. 位置感          ← 相对前高多远、这波涨了多少
```

> 第 0 步是**元规则**：定性错了，底下七步全废。所以 Skill 里写着「判断第一步是归类行情性质，每把尺都有有效期」。

## 为什么做这个

财经博主的内容每天在产生，但**看得多不等于用得上**。

语录合集解决不了新问题——你没法从「他说过一句要敬畏市场」推出「明天这票该不该走」。所以要蒸馏的是**决策链**：他遇到一个新图形，先看什么、用什么判据、判据失效时怎么办。

这个仓库是玟火框架的**第一个全量实战案例**：379 期日更播客，147.5 小时，491 万字转写，从零跑完整条流水线。

## 五条核心原则

| # | 原则 | 说明 |
|:---|:---|:---|
| 01 | **溯源** | 每条结论引文到「路径 + 时间戳」；转述不用「设置」以外的词 |
| 02 | **对账** | 可验证数字（点位、金额、日期）必须与外部数据源核对后才入库。句内算术自洽 ≠ 事实正确 |
| 03 | **存真** | 冲突不抹平。两个说法都有原文，就都保留、互相引用，裁决等新素材 |
| 04 | **棘轮** | 盲评分数只升不降；低于基线就回滚快照，绝不「先合进去再说」 |
| 05 | **说不懂** | 系统性风险、连亏处理、行业景气度——他自认无解的，Skill 里明写「未覆盖」，不替他补 |

## 25 个心智模型

| 组 | 模型 | 覆盖问题 |
|:---|:---|:---|
| **方法骨架** | M1 均线五线 · M2 参数自适应 · M3 多周期分工 · M4 量能验证 · M5 鱼嘴/粘合 · M6 位置感 | 怎么看图、怎么验信号 |
| **交易纪律** | M7 承认「赌」 · M8 风控四条 · N9 纪律制度化 · N14 风险随方向累积 · N16 割错比扛错便宜 | 赌多大、怎么认错 |
| **仓位结构** | N1 总仓楼层制 · N8 双层持仓 · N15 无趋势期是收割区 | 楼层怎么定、底仓怎么守 |
| **定性与点位** | N4 点位算法 · N5 先定性 · N11 破位程序 · N12 档位阶梯 · N13 确认是复数 | 破没破、算不算站稳 |
| **资金与大盘** | N3 分布与代理读数 · N6 跟钱反人 · N7 量能语境读法 · N10 大侠（对手盘） | 钱在哪、谁在接 |
| **时间与底细** | N2 时间是独立坐标 · M9 用基本面定性质 | 还有几天、这公司底细 |

> 六个组不是分类学，是**回答问题的入口**：被问「该止损吗」走纪律组，被问「大盘怎么看」走资金组。

## 蒸馏循环：6 个阶段

玟火框架的流水线。**文件即断点**——每个阶段落盘，新会话读 `PIPELINE_STATE.md` 就能续跑。

```
Phase 0  立项      → 确认对象画像、素材清单、档位、领域红线
Phase 1  多维采集  → 8 个维度独立落盘，每维标来源与可信度
   🔴 门 1.5       → 人工确认：来源数 / 关键发现 / 矛盾清单
Phase 2  框架提炼  → 每条观点过三重验证，淘汰项留原因
   🔴 门 2.5       → 人工确认：模型方向对不对
Phase 3  SKILL 构建 → 每个模型写「触发识别 → 判断规则 → 例外」
Phase 4  质量验证  → QC 全表 + 真实数据对账 + 盲评三向
   🛑 棘轮门       → 本次 ≥ 上次才交付，否则回滚快照
Phase 5  注册与增量 → 版本三处同步，此后每批新素材走增量协议
```

---

## 棘轮机制：盲评只升不降

每一次改 SKILL 都要过盲评，分数低于上一次就回滚，不接受「先合进去再说」。

```
v0.1  盲评 6.4  ──┐
v0.2  盲评 8.3  ──┤ 七条硬约束 + 口语密度要求上线
v0.3  素材边界   ──┤ 风控四条落地、诚实边界体系化
v0.4  pair 63.5  ──┤ 播客侧全量纳入，63.5 : 26.5
v0.5  未重跑盲评 ──┘ 开场白、logo、注册方式（不动判断层，分数沿用 v0.4）
```

> 棘轮的意义不是「分越刷越高」，是**挡住局部退化**。人设 Skill 最容易犯的错是越改越像通用助手——这条机制就是防这个。

## 快速开始

```bash
# macOS / Linux：软链，改源码立即生效
ln -s "$PWD/眼哥" ~/.dsh/skills/yan-ge-perspective
```

```powershell
# Windows：目录联接，不需要管理员权限
New-Item -ItemType Junction `
  -Path "$env:USERPROFILE\.dsh\skills\yan-ge-perspective" `
  -Target "$PWD\眼哥"
```

安装后在新会话里说「用眼哥的视角看看这票」即可触发。

> [!IMPORTANT]
> **目录名必须等于 `SKILL.md` frontmatter 里的 `name`**（这里是 `yan-ge-perspective`）。
> 叫成 `眼哥` 会让加载器在解析时直接抛错，技能不会出现在技能目录里。

其它 Agent 工具（Claude Code / Codex 等）把 `SKILL.md` 放进各自的 `skills/<name>/` 目录即可，规则相同。

## 事故与修正（为什么这仓库的日志值钱）

[PIPELINE_STATE.md](PIPELINE_STATE.md) 记录了全程翻车与翻案，几个代表：

- **3800 / 2800 方向翻转**：两个数字都被 ASR 听错，单条算术线索无法定案——拉真实区间后确认逻辑对、数字全错。此后立规：点位必须对账后才入库
- **「炒股不是一天的游戏」编造案**：改写主语 + 标错期次 + 虚构延展，靠脚本自验抓住。此后 v2 模板强制 `verify_quotes.py` 100% 重抄比对
- **三次检测工具自身出错**：归并比虚高、全线误报压平、对账表漏格——每次都是抽原始数据翻案。元教训：**先验证工具，再信结论**
